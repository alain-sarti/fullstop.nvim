# `locate` reports the body slot — treesitter is trusted for structure, not just position

`locate` now tells `analyze` one thing beyond position: the construct's **body slot** — `none` | `statement` | `block` | `unknown`, read off the grammar's own body fields (`consequence`, `alternative`, `body`, `handler`, `finalizer`) plus a positional check for wrapper anchors that carry no body field of their own (`export_statement`, `lexical_declaration`). This narrows ADR-0002's "treesitter is trusted for **position** only" clause, which was the direct cause of the reported bug: `analyze`'s three head classifiers ask *"does this text start with a block keyword?"* and its callers used the answer for *"does this construct still need a body?"*. Those two questions diverge the moment the body is already there — `if (test) foo();`, `if (!a) return`, `if (a) {…}` all start with `if` — and `apply` then spliced at the end of the **body** rather than the head, giving the next statement the `{ }` block.

The rejected alternative was a text heuristic in `analyze` (scan past the head's balanced condition and see whether anything follows). It stays pure and needs no new argument, but it re-derives from characters what the tree already states exactly, and it cannot tell `if (a) foo(() => { })` — body filled, block belongs to an argument — from `if (a) { … }`. The grammar answers structural questions; `analyze` keeps every *meaning* decision (what to insert, what terminates, when to Decline) and remains zero-`vim.*`, string-only, with the slot arriving as a plain string it can be unit-tested against. `unknown` is the honest fourth value rather than a lie: an `ERROR` anchor has no fields to read, so `analyze` falls back to its own text check in a lane that never overlaps the grammar's.

The load-bearing consequence, and the reason this is hard to reverse: a filled slot on a **later line** means the region is **capped at the head** and the body is orphaned below the new closing `}` — so `if (test)` + `foo();` completes to an empty block with `foo();` outside it. That changes what the program means (`foo()` stops being conditional) while staying purely additive per ADR-0001, revertible in one `u`. The alternative — reaching down and pulling the body inside the block — would have made `apply` a multi-edit, line-moving component, which the "one edit, one undo step" contract rules out. Firing *on* that body re-anchors onto it instead, because the cursor selects.
